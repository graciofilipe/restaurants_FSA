# Agent Spec: FSA Restaurant Explorer Evaluation & Observability

## Overview
This specification establishes the `agents-cli` Quality Flywheel and Observability framework for the FSA Restaurant Explorer project. It defines a unified evaluation harness and telemetry setup covering both the ADK Google Maps Grounding Agent (`app/maps_agent`) and the BigQuery Culinary Anthropologist 6-Pillar Profiler (`scripts/bq_scripts.py`). The project adopts a prototype-first scaffolding model (`--prototype`), establishing local evaluation datasets, custom hybrid Python/LLM metrics, and Cloud Trace observability.

## Example Use Cases

### 1. ADK Maps Agent Grounding & Extraction
- **Input**: Restaurant name and address (e.g., `"Taste of Sichuan, 123 High St, London E1 6AN"`).
- **Agent Action**: Uses `GoogleMapsGroundingTool` to ground address and fetch Google Maps details.
- **Expected Output**: Strict JSON dictionary containing `cuisine_type`, `review_count` (int), `average_rating` (float), and `summary` (string).
- **Evaluation**: Validated for schema compliance (deterministic Python metric) and extraction grounding (LLM judge).

### 2. Culinary Anthropologist 6-Pillar Scoring
- **Input**: Restaurant metadata, menu details, and review text.
- **Model Action**: Evaluates the restaurant against the 6 pillars (Value & Volume, Demographic/Community, Linguistic Signal, Geographic Precision, Culinary Uncompromisingness, Establishment Integrity) and computes a composite `match_score` (0-100).
- **Expected Output**: Raw JSON object conforming to the 6-pillar schema.
- **Evaluation**: Evaluated by `gemini-3.5-flash` judge assessing adherence to the user's specific culinary lens and strict exclusion penalties (e.g., penalizing cafes/fast food).

### 3. Distributed Telemetry & Latency Profiling
- **Action**: End-to-end execution of agent queries from Streamlit or evaluation CLI.
- **Expected Output**: OpenTelemetry spans exported to Cloud Trace showing breakdown of Vertex AI model latency, Maps tool execution, and BigQuery query times.

## Tools Required
- **GoogleMapsGroundingTool**: Vertex AI ADK tool for grounding restaurant locations and Maps details. Auth via Google Cloud ADC.
- **BigQuery Client & Vertex AI SDK**: `google-cloud-bigquery` and `google-genai` / `vertexai` for data ingestion, BQML integration, and evaluation grading.
- **Cloud Trace / OpenTelemetry**: Exporting span telemetry for agent invocations and tool calls.

## Constraints & Safety Rules
- **Modern Model Enforcement**: Only current generation models (`gemini-3.5-flash` or `gemini-3.1-pro`) are permitted; all legacy models (`gemini-2.5-flash`, `gemini-1.5-*`, `gemini-2.0-*`) are strictly prohibited.
- **Structured Output Integrity**: Agents and LLM prompts must enforce native structured JSON outputs without markdown wrappers (` ```json `) or introductory preamble text.
- **ADK Naming Convention**: The ADK application name in `app/maps_agent/agent.py` must match its containing directory (`maps_agent`) to adhere to ADK 2.0 runtime standards.
- **Code Preservation**: Existing Streamlit UI workflows and BigQuery persistence schemas must remain intact and backward-compatible.

## Success Criteria
1. **Eval Dataset Coverage**: Minimum of 5 canonical evaluation cases in `tests/eval/datasets/restaurant_eval.json` representing diverse restaurant profiles (hyper-local authentic gems, generic tourist spots, cafes/excluded venues).
2. **Deterministic Schema Accuracy**: `100%` pass rate on the deterministic Python metric `json_schema_validity` for all test cases.
3. **Qualitative Rubric Threshold**: Average score `>= 0.85` on `culinary_6_pillar_rubric` evaluated by `gemini-3.5-flash`.
4. **Cloud Trace Verification**: `100%` of evaluation and test runs successfully emit root and tool execution spans visible in Cloud Trace.
